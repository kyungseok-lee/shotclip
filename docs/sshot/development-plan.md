# 단계별 개발 순서

현재 완료 범위는 단계 0의 문서입니다. 단계 1부터는 사용자의 후속 개발 요청 이후 진행합니다. 순서를 건너뛰어 권한·좌표·클립보드에 관한 검증되지 않은 가정을 제품 코드에 고정하지 않습니다.

| 단계 | 작업 및 산출물 | 완료 조건 | 의존 |
| --- | --- | --- | --- |
| 0. 기준 문서 | 공통 규약, README, 요구사항, 설계, 계획, 검증, 인수인계 | 문서 독립 리뷰, 링크 확인, 구현 파일 없음, Git 원격 반영 확인 | 없음 |
| 1. 기술 검증과 결정 | 공식 문서 확인, 최소 실험으로 권한·캡처·좌표·UI 제외·clipboard·hotkey 확인. 실험 환경/결과와 D01~D05·D09 기록 | 실패 경로 포함 실험 증거 확보. R09 보존 정책 확정. 최소 OS/API/권한/단축키·화면 경계·실행 생명주기 결정 문서 | 구현 요청, 단계 0 |
| 2. 앱 골격 및 상태 | 프로젝트 생성, 메뉴 막대·설정·단축키·권한 안내·상태 coordinator. D06~D07 확정 | 전역 진입, 취소/재호출/권한 실패의 상태 테스트 통과. 캡처 없는 UI 흐름 수동 확인 | 단계 1 |
| 3. 두 선택 모드 | 고정 마스크 이동·리사이즈·확정, 드래그 즉시 선택, 디스플레이 좌표 mapper | 두 모드와 역드래그/음수 좌표/배율/키보드/화면 변경 검증. 잘못된 선택은 캡처 안 함 | 단계 2 |
| 4. 캡처와 클립보드 | capture service, overlay exclusion, 이미지 인코딩, clipboard service, 복사 알림·UI 종료 | 실제 화면과 픽셀 비교. 취소·실패의 기존 clipboard 유지. 텍스트 앱이 아닌 이미지 지원 앱에 ⌘V 확인 | 단계 3 |
| 5. 안정성 및 회귀 | 권한 철회·타임아웃·중복 입력·화면 분리·sleep/wake·반복 세션 검증, 개인정보 점검 | 검증표의 MVP 필수 항목 통과. 독립 verifier 증거, 남은 결함·지원 한계 기록 | 단계 4 |
| 6. 배포 준비 | D08 확정, release 설정·서명·notarization·설치/제거 문서, 사용자 가이드 | 새 사용자/깨끗한 머신에서 Gatekeeper와 권한 흐름 및 두 모드 동작 확인. 배포 artifact와 버전 기록 | 단계 5 |

각 단계는 작은 변경 단위로 작성하고 별도 reviewer/verifier가 검토합니다. 문서와 구현이 다르면 구현 전에 요구사항 변경 여부를 명시합니다. 필요 테스트가 실패하면 다음 단계 완료를 선언하지 않습니다.

## 작업 단위 예시

후속 개발자는 다음 순서로 이슈를 나눌 수 있습니다: API/OS 결정 → 단축키와 권한 → coordinator → 좌표 변환 → mask 선택 → drag 선택 → 캡처 제외 처리 → clipboard commit → 실패 복구 → 운영 검증 → 배포. 이슈마다 요구사항 ID, 변경 파일, 검증 명령 또는 수동 절차, 완료 증거를 남깁니다.

문서 단계에서는 앱 테스트가 없습니다. 구현 단계의 정확한 빌드·테스트 명령은 프로젝트가 생성된 뒤 README와 검증 문서에 기록합니다. 아직 존재하지 않는 scheme이나 실행 명령을 사용 가능한 것으로 제시하지 않습니다.
