# 검증 계획과 요구사항 추적

아래 표는 요구사항별 검증 계획입니다. 실행한 항목과 미실행 항목은 [QA 실행 기록](qa-results.md)에 구분합니다. 자동 테스트는 순수 변환·상태·오류 분기처럼 재현 가능한 로직에, 수동 테스트는 실제 권한·화면 합성·다른 앱 붙여 넣기에 사용합니다.

## 핵심 수동 절차

R14는 표시명·아이콘 구성 및 stable bundle ID/실행 파일/설치 경로/feed/공개키 유지 여부를 코드·plist·빌드로 검사합니다. 설정 창은 권한·단축키·업데이트 상태의 레이아웃과 기존 action 연결을 별도 reviewer가 확인합니다. 실제 0.3.0 설치·UI 관찰 전에는 예정으로 기록하고, 긴 캡처 QA는 사용자 인수 범위를 유지합니다.

R13은 업데이트 구성 누락·HTTP URL·잘못된 공개키에서 비활성화됨을 확인하고, 실제 서명 배포 환경에서 올바른 업데이트와 잘못된 archive 서명 거부를 각각 검사합니다. 이전 버전에서 업그레이드한 뒤 앱 식별자·서명·설정 유지와 화면 기록 권한·두 캡처 모드를 확인합니다. 빌드 성공만으로 실제 자동 업데이트를 통과로 표시하지 않습니다.

1. 합성 격자 화면과 좌표 표식을 띄웁니다. 기본 화면, 좌측/상단 음수 원점 화면, Retina/비 Retina 환경에서 각 모드로 네 모서리와 작은 영역을 캡처합니다. 선택 논리 rect, 기대 픽셀 크기, 실제 크기, 가장자리 일치 여부를 비교합니다.
2. 기존 클립보드에 식별 가능한 텍스트·이미지·가능하면 여러 pasteboard 타입을 넣습니다. Escape, 클릭만 하고 종료, 권한 거부·철회, 캡처 오류, 인코딩 오류, clipboard write 오류를 발생시킵니다. 데이터와 타입 보존을 검사합니다. 다른 앱의 동시 clipboard 변경 시 덮어쓰기 정책도 검사합니다.
3. 단축키를 연속 호출하고 선택 중·캡처 중·clipboard 기록 중 각각 재호출합니다. 중복 오버레이·캡처·알림이 없고 다음 호출이 정상 동작하는지 확인합니다.
4. 선택 중 모니터를 분리하거나 배율·해상도를 변경합니다. 세션이 안전하게 취소되고 기존 clipboard가 보존되는지 확인합니다. 잠자기/깨우기 후 다시 캡처합니다.
5. 마스크와 핸들이 보이는 상태에서 캡처하여 결과에 UI가 없는지 검사합니다. Preview 및 이미지 입력을 지원하는 문서/메신저 앱에 사용자가 직접 ⌘V를 누릅니다. 붙여 넣기를 지원하지 않는 입력란 실패는 캡처 실패와 구분합니다.
6. 배포 단계에서는 실제 서명 artifact를 새 사용자 계정 또는 별도 머신에서 실행하여 Gatekeeper, 권한 안내, 거부 후 복구, 앱 재설치/업데이트 흐름을 확인합니다.

권한 상태 변경·오류 주입은 개발 환경에서 재현하고 사용자 데이터를 테스트 재료로 사용하지 않습니다. 하드웨어가 없으면 해당 지원 범위는 미검증으로 남기며 통과로 표시하지 않습니다.

## 증거 기록 형식

각 실행은 날짜, 커밋, macOS/Xcode 버전, CPU 아키텍처, 디스플레이 배치·배율, 권한 상태, 절차, 기대/실제 결과, pass/fail, 관련 요구사항, 결함 ID를 기록합니다. 결과 이미지는 개인정보 없는 합성 화면만 사용하며 저장소 추가 여부를 별도로 판단합니다.

## 현재 문서 검증

상대 링크가 존재하고 R01~R12가 설계·개발 단계·검증표에 연결되어 있는지 확인합니다. 별도 리뷰에서 구현 금지 준수, 미확정 결정 분리, 인수인계 가능 여부를 검토합니다. Git push는 원격 브랜치와 로컬 HEAD의 commit ID 일치로 확인합니다.
