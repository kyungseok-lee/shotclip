## Developer reading route

Read requirements → design → implementation plan → verification. These documents describe current behavior and source-backed boundaries; recorded QA evidence is separate from planned or unrun checks.

| Read | Purpose |
| --- | --- |
| [Product plan](product-plan.md) · [Requirements](requirements.md) | Capture-to-clipboard scope and acceptance criteria |
| [Design system](design-system.md) · [Architecture](architecture.md) | Interface behavior, bilingual layout and service boundaries |
| [Development plan](development-plan.md) | Ordered work and requirement/design trace |
| [QA plan](qa-plan.md) | Production builds, the separate development QA app and reproducible checks |
| [Verification](verification.md) · [QA results](qa-results.md) | Coverage and actual evidence with limits |
| [Technical validation](technical-validation.md) | Official API references and technical findings |
| [Update operations](update-operations.md) | Packaging, signed updates and delivery procedures |
| [Handoff](handoff.md) | Current working state and next steps |

## 한국어

설치·화면 기록 권한·영역/고정 캡처·단축키·미리보기/PNG 저장·설정·문제 해결은 [한국어 사용 안내](../../README.ko.md)를 먼저 읽으세요.

개발 문서는 요구사항 → 설계 → 구현 계획 → 검증 순서로 읽습니다. 빌드와 별도 개발 QA 앱은 [QA 계획](qa-plan.md), 현재 작업 상태는 [인수인계](handoff.md), 실제 수행한 검증과 한계는 [QA 결과](qa-results.md)에 있습니다. 문서 변경만으로 새 앱 동작 검증을 통과했다고 간주하지 않습니다.
